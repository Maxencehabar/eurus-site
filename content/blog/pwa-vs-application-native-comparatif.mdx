# PWA vs Application Native : quel choix pour votre projet en 2026 ?

Votre boss veut une "app mobile". Mais avez-vous vraiment besoin d'une app sur l'App Store ? Ou est-ce qu'une PWA (Progressive Web App) suffirait — pour moitié prix ?

En 2026, cette question n'a jamais été aussi pertinente. Les PWA ont rattrapé 90% des fonctionnalités natives. Mais "90%" n'est pas "100%". Ce guide vous aide à trancher.

## TL;DR — Le verdict rapide

| Critère | PWA | App Native |
|---------|-----|------------|
| **Coût développement** | 15-40K€ | 40-100K€ |
| **Time-to-market** | 2-3 mois | 4-6 mois |
| **Performance** | 85-95% du natif | 100% (référence) |
| **Accès fonctionnalités device** | 80% | 100% |
| **Distribution** | URL directe | App Store / Play Store |
| **Engagement utilisateur** | +65% vs site web | Référence |
| **Offline** | Oui (Service Workers) | Oui (natif) |

**En 3 points :**
- **Choisissez une PWA** si votre app est content-first, si vous voulez éviter les stores, ou si le budget est serré
- **Choisissez le natif** si vous avez besoin de Bluetooth, NFC, capteurs avancés, ou de la visibilité App Store
- **Le gap performance** a chuté à moins de 10% pour les apps business classiques en 2026

## Qu'est-ce qu'une PWA ?

Une Progressive Web App est un site web "augmenté" qui se comporte comme une application native : installation sur l'écran d'accueil, fonctionnement offline, notifications push.

**Chiffres clés 2026 :**
- **70% des utilisateurs mobiles** ont accès à la 5G (2025), éliminant l'avantage performance du natif
- **50-70% de réduction des coûts** de développement vs natif (source : Google Case Studies)
- **3-5x plus d'utilisateurs atteints** vs app native (pas besoin de téléchargement)
- **65% d'augmentation de l'engagement** vs site web classique (étude Twitter PWA)
- **20% de réduction du bounce rate** (LANSA 2025)

**Exemples de PWA célèbres :**
- Twitter Lite (Inde, marchés émergents)
- Starbucks (commande en ligne)
- Pinterest
- Uber
- Spotify (version web)

## Qu'est-ce qu'une application native ?

Une app native est développée spécifiquement pour iOS (Swift/SwiftUI) ou Android (Kotlin), ou via un framework cross-platform (Flutter, React Native) qui compile en natif.

**Chiffres clés 2026 :**
- **2.87 millions d'apps** sur Google Play Store
- **1.96 million d'apps** sur Apple App Store
- **Taux d'abandon** : 25% des apps téléchargées ne sont jamais ouvertes
- **Coût moyen de maintenance** : 15-20% du coût initial par an
- **Commission stores** : 15-30% sur les achats in-app

**Ce que le natif offre exclusivement :**
- Accès complet aux APIs hardware (Bluetooth LE, NFC, ARKit/ARCore)
- Performances maximales (jeux, AR/VR)
- Présence sur les stores (découvrabilité, crédibilité)
- Widgets iOS/Android
- Intégrations système profondes (Siri, Google Assistant)

## Comparaison détaillée

### Performance

Le mythe : "les PWA sont lentes". La réalité 2026 : **l'écart perceptible est inférieur à 10%** pour les applications business.

**Benchmark 2025 (app e-commerce type) :**
- Temps de chargement initial : PWA 1.8s vs Native 1.2s
- Navigation entre pages : quasi-identique avec bonne PWA
- Animations : PWA 55-58 FPS vs Native 60 FPS
- Consommation batterie : PWA +10-15%

**Ce qui fait la différence** : la qualité du développement. Une PWA bien optimisée bat une app native mal codée. On a vu des PWA Lighthouse 100/100 plus fluides que des apps natives bloatées.

**Limite réelle** : les jeux, la réalité augmentée, et le traitement vidéo lourd restent le domaine du natif.

### Coût de développement

C'est le vrai argument massue des PWA.

**PWA :**
- 1 codebase pour web + "app" mobile
- Pas de processus de validation App Store
- Déploiement instantané (URL)
- **Coût moyen MVP : 15-40K€**

**App Native (cross-platform Flutter/RN) :**
- 1 codebase mais compilation spécifique
- Validation App Store (1-7 jours)
- Comptes développeur (99€/an Apple, 25€ one-time Google)
- **Coût moyen MVP : 40-80K€**

**App Native (iOS + Android séparés) :**
- 2 codebases à maintenir
- 2 équipes ou 1 équipe polyvalente rare
- **Coût moyen MVP : 80-150K€**

**Notre calcul Eurus** : sur un projet type "app de service" (catalogue, réservation, compte utilisateur), la PWA coûte **50-60% moins cher** et se livre **40% plus vite**.

### Fonctionnalités accessibles

Voici ce qui marche (ou pas) en PWA en 2026 :

**✅ Fonctionnel en PWA :**
- Installation sur écran d'accueil
- Notifications push (Android full, iOS depuis iOS 16.4)
- Mode offline (Service Workers)
- Caméra et micro
- Géolocalisation
- Paiements (Web Payment API)
- Partage (Web Share API)
- Clipboard, vibration
- WebGL (3D basique)

**⚠️ Limité en PWA :**
- Bluetooth (Web Bluetooth, support partiel)
- NFC (Chrome Android uniquement)
- Contacts et calendrier (limité)
- Background sync (restrictions)
- Accès fichiers (File System Access API, nouveau)

**❌ Impossible en PWA :**
- ARKit/ARCore (réalité augmentée native)
- Widgets home screen
- CallKit/intégration téléphone
- HealthKit/Google Fit
- In-app purchases via stores
- Siri/Google Assistant

**Règle simple** : si votre fonctionnalité clé est dans la liste "Impossible", vous devez passer en natif.

### Distribution et acquisition

**PWA — avantages :**
- Pas de téléchargement = friction zéro
- Partageable par simple URL
- SEO-friendly (indexé par Google)
- Mise à jour instantanée (pas d'attente store)
- Pas de commission 15-30%

**App Native — avantages :**
- Visibilité App Store / Play Store (ASO)
- Crédibilité perçue ("une vraie app")
- Pré-installation possible (deals constructeurs)
- Référencement store search

**Statistique clé** : les PWA touchent **3-5x plus d'utilisateurs** car elles éliminent la friction du téléchargement. Mais les apps natives ont un meilleur taux de rétention (l'icône sur l'écran rappelle l'app).

### Cas d'usage idéaux

**Choisissez une PWA pour :**
- Apps content-first (médias, blogs, catalogues)
- E-commerce (Starbucks, AliExpress style)
- Apps internes entreprise
- Marchés émergents (bandwidth limité)
- MVP / validation de concept
- Quand vous voulez éviter la commission Apple/Google

**Choisissez le natif pour :**
- Apps nécessitant Bluetooth/NFC (IoT, paiement)
- Jeux et expériences AR/VR
- Apps santé/fitness (HealthKit, capteurs)
- Quand la présence App Store est stratégique
- Apps avec beaucoup de fonctionnalités offline complexes
- B2C grand public où la crédibilité "app store" compte

## FAQ

### Les PWA fonctionnent-elles sur iPhone en 2026 ?

Oui, avec des nuances. Depuis iOS 16.4 (2023), Safari supporte les notifications push pour les PWA installées. Le mode offline fonctionne. Mais Apple reste plus restrictif qu'Android : pas d'installation automatique, icône "ajoutée" pas native, et quelques APIs manquantes. Pour une app grand public B2C sur iPhone, le natif reste recommandé.

### Une PWA peut-elle être sur l'App Store ?

Techniquement oui, via des wrappers comme PWABuilder ou Capacitor. Mais Apple rejette régulièrement les "apps qui sont juste des sites web". Si votre PWA n'ajoute pas de valeur significative vs le site, elle sera refusée. Google Play est plus permissif avec les TWA (Trusted Web Activities).

### Quelle est la différence entre PWA, app hybride, et app native ?

- **PWA** : site web installable, tourne dans le navigateur, accès limité au hardware
- **App hybride** (Ionic, Cordova) : site web emballé dans une coque native, accès hardware via plugins
- **Cross-platform** (Flutter, React Native) : code unique qui compile en vrai natif, accès complet
- **Natif pur** (Swift, Kotlin) : code spécifique à chaque plateforme, performance maximale

En 2026, les apps hybrides (Cordova) sont quasi-obsolètes. Le choix est entre PWA et cross-platform (Flutter/RN).

### Combien coûte la maintenance d'une PWA vs app native ?

PWA : ~10% du coût initial par an (mises à jour, hébergement, monitoring).
App native : ~15-20% par an (+ mises à jour obligatoires pour compatibilité iOS/Android).

L'écart vient des cycles de mise à jour forcés par Apple/Google. Chaque nouvelle version iOS peut casser des choses. Une PWA n'a pas ce problème.

### Peut-on convertir une PWA en app native plus tard ?

Oui, mais ce n'est pas une conversion — c'est une réécriture. Le code PWA (HTML/CSS/JS) ne se "transforme" pas en Flutter ou Swift. Par contre, vous pouvez réutiliser : le design system, les APIs backend, la logique métier (si en JS, réutilisable en React Native). Comptez 50-70% du coût d'un projet from scratch.

La PWA n'est plus le "plan B pas cher". En 2026, c'est une vraie alternative stratégique au natif. Twitter, Starbucks, Pinterest l'ont prouvé : on peut avoir une excellente expérience utilisateur sans passer par les stores.
